The Search for
Constrained Random Generators

Among the biggest challenges in property-based testing (PBT) is the constrained random generation problem: given a predicate on program values, randomly sample from the set of all values satisfying that predicate, and only those values. Efficient solutions are critical, since the executable specifications used by PBT often have preconditions that input values must satisfy to be valid test cases, and satisfying values are often sparsely distributed.

We propose a novel approach using ideas from deductive program synthesis: a set of synthesis rules, based on a denotational semantics of generators, that give rise to an automatic procedure for synthesizing correct generators. Our system handles recursive predicates by rewriting them as catamorphisms and matching with appropriate anamorphisms — theoretically simpler than other approaches to synthesis for recursive functions, yet still extremely expressive.

Our implementation, Palamedes, is an extensible library for the Lean theorem prover. The synthesis algorithm is built on standard proof-search tactics, reducing implementation burden and letting the algorithm benefit from further advances in Lean proof automation.

Motivation

The constrained random generation problem.

To test a property like the one above, property-based testing frameworks sample thousands of trees and checks the property on each. But the property is only meaningful when the tree is already a valid BST. If you sample trees naïvely, almost all of them will be discarded as invalid.

An expert can hand-write a generator that produces valid binary search trees by construction. But writing such generators is fiddly, error-prone, and — as studies of testing practitioners show — a chore even experts would rather avoid. Palamedes writes them for you.

A worked example

Correct by construction generators, automatically derived from predicates.

Call generator_search on a predicate, and Lean synthesizes a generator during compilation.

What you write
BST.lean 
def isBST (t : Tree Nat) (lo hi : Nat) : Bool :=
  match t with
  | leaf => true
  | node l x r =>
      lo <= x && x <= hi &&
      isBST l lo (x - 1) &&
      isBST r (x + 1) hi

-- ask Palamedes for a generator:
def genBST (lo hi : Nat) : Gen (Tree Nat) := by
  generator_search (fun t => isBST t lo hi)

def genBST (lo hi : Nat) : Gen (Tree Nat) :=
  if lo > hi then
    pure leaf
  else
    pick
      (pure leaf)
      (do let x <- choose lo hi
          let l <- genBST lo (x - 1)
          let r <- genBST (x + 1) hi
          pure (node l x r))
Key Ideas

Contributions in the Paper

Deductive Synthesis Rules

We propose a system of deductive synthesis rules for correct generators, proven correct relative to a denotational semantics of generators.

Recursive Data Structures

We extend the resulting synthesis algorithm to work for generators of recursive data types, using tools from the literature on recursion schemes to greatly simplify the synthesis process.

Implementation

We offer Palamedes, an implementation of our synthesis procedure embedded as a library in the Lean proof assistant. This implementation strategy achieves performant synthesis that also maintains mechanized proofs of correctness, while borrowing key parts of the algorithm from Lean’s existing infrastructure.
